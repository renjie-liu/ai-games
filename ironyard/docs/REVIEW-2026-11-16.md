# Ironyard 0.5.1 reliability review

Reviewed from remote `main` (`05042aa`) and the pending Muse branch (`include-muse-tournament`, `ad21379`). This patch builds on the Muse branch so all 20 entrants remain available. It changes tournament correctness and worker lifecycle, without changing bot strategies, weapon values, maps or the ladder rating formula.

## Reproduced problems and fixes

| Problem | Evidence | Fix |
|---|---|---|
| Failed custom tournament games earned draw points | An unattributed worker exception produced `winner: -1`; both entrants gained one point. Returned tick errors were also ignored. | Shared normalization for browser, CLI and MCP. Unfinished/runtime-error games are unscored. Exceptions attributed to exactly one team are forfeits. Zero-game entrants are unranked. |
| CPU contention could alter the simulated battle | Feeding the engine a clock that advances 300 ms per timing read cut off both healthy Rookie controllers at simulation time 0.15 s; a 1 ms clock did not. | Timing stays in CPU telemetry only. External worker watchdogs still interrupt hanging controllers. Engine version increments to 0.5.1 to invalidate old cached outcomes. |
| Browser work could time out before starting | Every job started a watchdog immediately while one synchronous worker processed the queue. Rebuilding a worker left pending promises unsettled. | Dispatch one job at a time and start its watchdog on dispatch. Cancellation, errors and source changes settle all affected jobs and clear timers. Ignore messages from obsolete workers. |
| Tournament and arena interfered; Watch started a different match | Both shared a worker; Watch chose a random map and used mutable settings. | A separate tournament worker, frozen tournament inputs, Stop with partial results, and Watch using the completed match's full configuration and source snapshot. |
| Closing the Node pool left callers waiting | Active and queued jobs had no immediate rejection; calls after close could remain queued. | Close rejects pending work, disallows new jobs and prevents respawn. Unexpected worker exits and failed message cloning reject promptly. |
| CLI repeatedly read controller files | Source lookup occurred for both teams on every match. | Snapshot source once per entrant. A complete N-bot round robin now reads N sources rather than two per match, and edits during a run cannot change later matches. |
| Seeking a paused replay to its end hid the result | The scrub handler always hid the banner; only an actively playing animation could show it again. | Seeking to the final slider position sets the exact duration, pauses playback and immediately displays the result. |

## Verification

Regression tests cover failed/unfinished results, attributed forfeits, duplicate entrants, partial completion, clock-independent gameplay, queued watchdogs, cancellation, source replacement, pool closure and worker recovery. Bookkeeping reproduces the standings from all 2016 previously recorded seven-entrant tournament results.

CLI integration uses a controller that throws after nine simulation seconds and checks a nonzero exit code, two unscored games and zero draw points. MCP integration exercises late runtime failures and an opponent's invalid design over both stdio and HTTP. Browser integration covers normal editing/playback, the infinite-loop watchdog, independent tournament/arena runs, stopping with partial results, exact Watch configuration despite later edits, and provisional error-only standings.

- `npm test`: 48 tests passed.
- `npm run test:mcp`: stdio, HTTP and token-protected HTTP passed, including the new failure cases.
- Full 20-bot ladder: **4560 new matches** under engine 0.5.1 (3040 solo, 800 doubles, 720 triples), zero errors. Comparing the resulting snapshot with 0.5.0 gave identical standings and author tables in all modes, including every displayed rating and win/draw/loss count. `LEADERBOARD.md` and the embedded snapshot are refreshed to 0.5.1.
- `CHROME=/usr/bin/chromium IRONYARD_TEST_BASE_URL=http://127.0.0.1:8766/ npm run test:ui`: passed against the built page served over local HTTP, including the mobile layout and CDN-failure fallback.
- `npm run build` and `git diff --check`: passed. No controller source files changed.

## Limits

Watch regenerates a deterministic replay from frozen inputs; it does not store every match's full frame stream. Stop preserves completed browser results for the current page session, but cannot resume an interrupted schedule. Watchdogs still depend on host time, and their reported failures require review. Weapon balance and broader strategy tuning remain separate work; this patch is not a new model benchmark.
